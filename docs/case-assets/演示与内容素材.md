## 对外统一介绍

REEL LAB 是面向 TikTok Shop 卖家、跨境品牌和内容团队的短视频内容工作区。输入商品链接后，团队可以把商品事实和评论整理为不同内容角度，批量生成带分镜的脚本，选出 Top20，再把素材需求交给拍摄人员。视频发布后，导入自有表现数据，系统整理 Content DNA 并据此规划下一轮。当前展示用真实商品研究和模拟业绩完成两轮闭环，用来验证工作流。

## 公众号图文路线

建议标题：**一个商品链接，如何变成100条可拍脚本？**

开场：商品资料、脚本表、拍摄清单和投流数据往往分散在不同地方。这个案例把它们放进同一个工作区，演示从商品理解到第二轮内容的完整过程。

图文顺序：

1. `01-home.png`：先展示商品和100条内容的总览，说明这一轮的结果是什么。
2. `07-angle-matrix.png`：解释13类角度与人设组合，展示差异化如何产生。
3. `09-storyboard.png`：放大逐镜头动作，说明产物如何交给摄影师。
4. `12-materials.png`：展示素材缺口、复用脚本和负责人。
5. `15-performance.png`：保留“模拟表现数据”提示，讲清复盘口径。
6. `03-workflow.png`：收束到两轮产物和迭代依据，附使用入口。

可直接使用的收尾：这次演示验证的是研究、生成、拍摄规划和复盘之间的数据闭环。真实运营时，仍需要团队完成实拍、投放和业务数据回收，再判断哪些方向值得扩大测试。

## 60 秒短视频讲解稿

| 时段 | 画面 | 口播 / 字幕 |
| --- | --- | --- |
| 0–5秒 | 首页与商品链接输入 | 一个商品链接，能不能直接变成拍摄团队能用的100条方案？ |
| 5–13秒 | 商品洞察与评论证据 | 先读商品和评论，区分当前商品与关联单品，保留每条信息的来源。 |
| 13–23秒 | 角度矩阵 → Top20 | 再按痛点、测评、教程等13类角度规划内容，结合不同人设筛选Top20。 |
| 23–35秒 | 逐秒分镜近景 | 打开一条，前三秒说什么、镜头拍什么、字幕怎么写、需要哪些素材，都有明确安排。 |
| 35–43秒 | 素材工厂 | 摄影师拿到Shot List，按任务补拍；同类素材还能复用。 |
| 43–53秒 | 数据复盘，保留模拟标签 | 发布后导入表现，系统整理Content DNA。这里用模拟GMV演示学习机制，不代表真实收益。 |
| 53–60秒 | 两轮工作流 | 下一轮根据复盘调整方向，再生成新的内容。完整价值是把创作和复盘连起来。 |

画面来自当前应用截图；以上为剪辑脚本，未声称已渲染成视频。实际录屏时可保留鼠标点击、选择批次和打开分镜的动作。

## 10 分钟课程 / 客户演示

1. 0–1 分钟：介绍“商品事实 → 拍摄任务 → 数据反馈”的三个断点，说明本次数据边界。
2. 1–2 分钟：演示新建商品。网络不稳定时明确切换来源快照，不等待现场抓取。
3. 2–4 分钟：比较矩阵中的两个角度，逐条打开脚本；让学员说出各自需要拍的动作。
4. 4–6 分钟：切换口播和七维评分，展示素材任务分配与 Shot List 导出。
5. 6–8 分钟：选模拟数据组，讲清 CTR、CVR、ROAS 的分母和缺失值；查看 DNA 标签样本量。
6. 8–9 分钟：在增长工作流查看两轮批次依据，导出第二轮 Top20。
7. 9–10 分钟：总结应用边界，安排学员导入自己的商品 JSON，试生成15秒UGC。

互动练习：使用 `examples/product-import.json` 导入教学商品，再输入“只做15秒UGC”。挑选一条脚本，试读并标出无法在现场执行的镜头。评估标准是动作可执行、卖点有来源、时长可试读，而非文案是否热闹。

- 真实业务演示前替换数据并复盘，不把演示截图中的数值说成客户成绩。
