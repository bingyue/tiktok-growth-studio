## 一次性复演

先启动项目：

```bash
npm run dev
```

另开终端，在项目根目录执行：

```bash
npm run case:capture
npm run case:build
npm run case:verify
```

采集使用项目已有的 Playwright 和本机 Google Chrome。没有修改用户浏览器的标签或当前筛选状态。默认访问 `http://127.0.0.1:4348`，可用 `CASE_URL` 指定另一个本机演示服务。

采集动作会通过真实界面新建一个独立 Demo 商品工作区、完成两轮内容、再次导入同一组模拟表现以验证幂等更新，并导出结果。它会增加 Demo 记录，不会删除旧商品。不要指向未知的公网服务或真实生产环境。

实时读取失败时，脚本保存失败尝试到 `outputs/live-attempt.json`，再使用已取证商品快照；`outputs/run.json` 和素材页明确记录最终采用的模式。执行中截图可能属于实时读取尝试，应结合运行日志阅读，不能把失败尝试描述为成功实时抓取。

截图采集失败时不要将残留目录当成完整新交付。先查看 `capture.log`，修复后重跑；只有出现 `CASE COMPLETE` 且 `outputs/run.json` 与 `manifest.json` 属于同一次运行，才重新构建案例页。

`npm run case:build` 从 Markdown、截图清单和实际导出数据生成 `index.html`、`guide.html` 及其他文档 HTML。Markdown 是编辑源；不要只修改生成的 HTML。

## 截图选择原则

1. 优先展示有商品、脚本、分镜和结果的页面，不以空状态作为核心营销素材。
2. 保留任务实际状态、模拟数据标识、评论归属和规则评分限制。
3. 设置页只截能力状态，不展示 `.env`、令牌、私有账号或未经授权的客户数据。
4. 首页、Top20、分镜、复盘采用横屏画面；移动端另有 390 × 844 竖屏原图。
5. 长图适合作为课程讲解和公众号分段配图；短视频优先放大单条分镜，不把整张宽表压入竖屏。
6. 不修改真实数值，不给失败截图加“成功”文案，不把模拟竞品称为已验证爆款。

## 文件约定

- `screenshots/`：原始界面截图。
- `manifest.json`：截图清单、时间、视口与图注。
- `outputs/`：本次实际运行的两轮工作包、Top20、Shot List、复盘和运行证明。
- `examples/`：可替换的教学输入，文件名明确区分模拟表现。
- `使用说明.md`、`案例说明.md`、`输出示例.md`：使用与对外介绍。
- `演示与内容素材.md`：公众号、小红书、60秒口播与10分钟课程路线。
- `index.html`：本地可打开的素材总览，支持按阶段筛选截图。

校验脚本检查原始PNG、文档链接、教学输入格式、素材筛选、使用说明入口及移动端布局，结果保存到 `verification.json`。

这是可交付素材包，不会自动发布到公众号、小红书或其他外部平台。
